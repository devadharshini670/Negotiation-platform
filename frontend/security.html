Account & platform

Security & Privacy.

What's actually implemented behind your account — written plainly, not as marketing copy.

Password storage

Passwords are never stored in plain text.

Each password is salted and hashed with Werkzeug's PBKDF2 implementation before it ever touches the database. The platform itself cannot recover your password — only reset it via a one-time emailed link.

Login protection

Repeated failed logins are rate-limited.

After 5 incorrect attempts, an account is locked for 15 minutes, blocking further guesses even with the correct password.

Session handling

Sessions expire automatically.

You're signed out after 2 hours of inactivity. Session cookies are HTTP-only and same-site, so they can't be read by page scripts or sent from another site.

CSRF protection

Every action that changes data is verified.

Each session carries a server-issued token that must accompany every create/update request. Requests missing it, or carrying the wrong one, are rejected.

Per-user authorization

Your negotiations are yours alone.

Every negotiation is tied to the account that created it. Another signed-in user cannot view, act on, or even confirm the existence of your sessions — attempting to do so returns the same "not found" response as a made-up ID.

Email verification & reset

Ownership of your address is proven, not assumed.

New email-and-password accounts must verify their email before signing in, and password resets use single-use, time-limited links. Reset requests get the same answer whether or not an address is registered, so the form can't be used to find out who has an account.

Google & GitHub sign-in

Standard OAuth 2.0, handled entirely by the server.

You're sent to Google or GitHub to approve access, and the provider hands the server a one-time code that is checked against a per-attempt state value tied to your browser (blocking forged callbacks). The client secret and the provider's tokens never reach your browser, and the tokens aren't stored. We only accept an email address the provider itself has verified. If it matches an existing account, the sign-in method is linked to that account instead of creating a duplicate. If someone had registered that address without ever verifying it, their password is removed so only the real owner can use the account. Accounts created this way have no password.

Two-factor authentication

Optional, and applies to every way of signing in.

Turn it on under Account settings with any authenticator app. Codes work once, wrong codes count toward the same lockout as wrong passwords, and single-use recovery codes cover a lost phone. The same step is required after Google or GitHub sign-in.

Your data & your account

Export it or delete it yourself.

Download everything the platform holds about you as a JSON file, or permanently delete your account and all your negotiations. Deleting asks for your username, your password if you have one, and a two-factor code if it's on. You can also disconnect Google or GitHub, as long as another way to sign in remains.

Not implemented in this build: email-change flows and hardware security keys (WebAuthn).
